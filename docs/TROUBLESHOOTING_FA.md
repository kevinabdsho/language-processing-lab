## &#x2067;خروجی &#x2066;`len()`&#x2069; با تعداد «حروفی که می‌بینم» یکی نیست&#x2069;

&#x2067;&#x2066;`len()`&#x2069; تعداد code pointهای موجود در Python string را می‌شمارد، نه الزاماً تعداد graphemeهای ادراکی. combining marks و برخی توالی‌های Unicode می‌توانند تفاوت ایجاد کنند.&#x2069;

## &#x2067;&#x2066;`NFC`&#x2069;، `ي` را به `ی` تبدیل نکرد&#x2069;

&#x2067;این رفتار درست است. `ي` و `ی` دو code point مستقل‌اند و canonical equivalent نیستند. تبدیل آن‌ها یک تصمیم language-specific است.&#x2069;

## &#x2067;ZWNJ را نمی‌بینم&#x2069;

&#x2067;ZWNJ با کد &#x2066;`U+200C`&#x2069; یک نویسه‌ی نامرئی است. از &#x2066;`repr()`&#x2069; یا &#x2066;`ord()`&#x2069; و &#x2066;`unicodedata.name()`&#x2069; برای بررسی آن استفاده کنید.&#x2069;

## &#x2067;چرا &#x2066;`\d`&#x2069; رقم فارسی را پیدا می‌کند ولی &#x2066;`[0-9]`&#x2069; نه؟&#x2069;

&#x2067;در Python 3، &#x2066;`\d`&#x2069; به‌طور پیش‌فرض رقم‌های ده‌دهی Unicode را می‌پذیرد، اما &#x2066;`[0-9]`&#x2069; تنها کاراکترهای ASCII را هدف می‌گیرد.&#x2069;

## &#x2067;چرا `\b`، کلمهٔ `می‌روم` را دو بخش می‌کند؟&#x2069;

&#x2067;در regex پایتون، `\w` نیم‌فاصلهٔ `U+200C` را شامل نمی‌شود. بنابراین `\b` یک مرز وابسته به `\w`/`\W` است، نه مرز زبان‌شناختی واژهٔ فارسی. برای تست از raw string مانند `r'\b\w+\b'` استفاده کنید.&#x2069;

## &#x2067;چرا `bytes` یک توکن BPE گاهی decode نمی‌شود؟&#x2069;

&#x2067;در byte-level BPE یک توکن می‌تواند تنها بخشی از یک نویسهٔ چندبایتی UTF-8 باشد. تک‌تک توکن‌ها را decode نکنید؛ ابتدا با `b''.join(tokens)` همهٔ بایت‌ها را به هم بچسبانید و سپس decode کنید.&#x2069;
